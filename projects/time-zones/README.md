# Time Zones
Live city clocks and a meeting preview. The date/time input is interpreted in the device's local time zone; each city shows the same instant with its date, UTC offset, and approximate daytime/evening label. Native Intl/IANA data handles daylight saving. Nonexistent local times in the spring-forward gap are rejected; repeated fall-back times use the browser's earlier occurrence. Up to 12 valid, canonical time zones are stored in `dock-time-zones-v1`; presets, removal, persistence, and clipboard export are supported. No external requests, calendar integration, telemetry, account, or API key beyond the hub login. Device clock and browser time-zone data must be accurate. “Daytime” is an approximate clock range, not working-day or holiday awareness.
